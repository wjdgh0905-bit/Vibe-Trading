# 메뉴 막대

Source: https://developer.apple.com/kr/design/human-interface-guidelines/the-menu-bar

> Mac 또는 iPad에서 화면 상단의 메뉴 막대는 앱 또는 게임의 상위 레벨 메뉴를 표시합니다.

![선택된 메뉴가 표시된 macOS 메뉴 막대의 스타일화된 모양. 여섯 가지 색상으로 된 기존 Apple 로고의 빨간색을 은은하게 반영하는 빨간색 색조가 이미지에 적용됨.](https://developer.apple.com/images/com.apple.HIG/components-the-menu-bar-intro@2x.png)

Mac 사용자는 macOS 메뉴 막대와 매우 친숙하며 메뉴 막대를 통해 앱이 수행하는 작업을 알아보고 필요한 명령을 찾습니다. 앱 또는 게임이 macOS와 잘 어우러지도록 하려면 일관적인 메뉴 막대 경험을 제공하는 것이 중요합니다.

iPad의 메뉴 막대에 포함된 메뉴는 Mac의 메뉴와 유사하며 동일한 순서로 표시되고 친숙한 메뉴 항목 세트로 구성됩니다. 사람들이 Mac에 대한 경험을 통해 예상하는 메뉴 구조를 사용하면 iPad의 메뉴 막대도 즉시 이해하고 활용하는 데 도움이 됩니다.

iPadOS의 키보드 단축키는 macOS와 동일한 패턴을 사용합니다. 지침을 보려면 [표준 키보드 단축키](https://developer.apple.com/kr/design/human-interface-guidelines/keyboards#Standard-keyboard-shortcuts)의 내용을 참조하십시오.

![iPad의 앱 윈도우 일러스트. 화면 상단에 메뉴 막대가 있고 편집 메뉴가 열려 있음.](https://developer.apple.com/images/com.apple.HIG/kr/menu-bar-ipad-overview@2x.png)

메뉴 막대의 메뉴는 모든 유형의 메뉴가 갖는 대부분의 모양 및 동작 특성을 갖고 있습니다. 메뉴에 대한 일반적인 사항 및 메뉴 항목을 구성하고 레이블을 추가하는 방법에 대해 알아보려면 [메뉴](https://developer.apple.com/kr/design/human-interface-guidelines/menus)의 내용을 참조하십시오.

## 구조

메뉴 막대에 메뉴가 표시되는 경우, 아래 목록의 순서로 메뉴가 나타납니다.

- *앱 이름*(이 메뉴 제목에 사용할 앱의 짧은 이름을 제공하게 됨)
- 파일
- 편집
- 포맷
- 보기
- 앱 특화 메뉴(있을 경우)
- 윈도우
- 도움말

또한 macOS 메뉴 막대의 앞쪽에는 Apple 메뉴가 있고 뒤쪽에는 메뉴 막대 아이콘이 있습니다. 지침을 보려면 [macOS](https://developer.apple.com/kr/design/human-interface-guidelines/the-menu-bar#macOS)의 내용을 참조하십시오.

## 모범 사례

**기본 시스템 정의 메뉴 및 해당 순서를 지원하십시오.** 사람들은 익숙한 순서로 메뉴 및 메뉴 항목을 찾을 수 있기를 기대합니다. 대부분의 경우, 시스템에서 표준 메뉴 항목의 기능을 구현하므로 이를 따로 처리하지 않아도 됩니다. 예를 들어, 사람들이 표준 텍스트 필드에서 텍스트를 선택하는 경우 시스템은 편집 > 복사하기 메뉴 항목을 사용할 수 있도록 처리합니다.

**메뉴 항목 세트는 항상 동일하게 표시하십시오.** 메뉴 항목이 계속 표시되도록 하면 현재 상황에서는 사용할 수 없더라도 앱이 지원하는 동작을 배우는 데 도움이 됩니다. 메뉴 막대 항목이 실행 가능하지 않은 경우, 메뉴에서 가리는 대신 해당 동작을 비활성화하십시오.

**메뉴 항목 동작을 익숙한 아이콘으로 나타내십시오.** 아이콘은 사람들이 앱 전체에서 일반적인 동작을 인식하는 데 도움이 됩니다. 시스템과 동일한 아이콘을 사용하여 복사, 공유 및 삭제와 같은 동작이 나타나는 곳마다 표시하십시오. 자주 쓰는 동작을 나타내는 아이콘 목록을 보려면 [표준 아이콘](https://developer.apple.com/kr/design/human-interface-guidelines/icons#Standard-icons)의 내용을 참조하십시오. 추가 지침을 보려면 [메뉴](https://developer.apple.com/kr/design/human-interface-guidelines/menus)의 내용을 참조하십시오.

**포함된 표준 메뉴 항목에 정의되어 있는 키보드 단축키를 지원하십시오.** 사람들은 복사하기, 오려두기, 붙여넣기, 저장 및 프린트와 같이 이미 알고 있는 표준 메뉴 항목의 키보드 단축키가 사용 가능할 것이라고 예상합니다. 사용자 설정 키보드 단축키는 필요한 경우에만 정의하십시오. 지침을 보려면 [표준 키보드 단축키](https://developer.apple.com/kr/design/human-interface-guidelines/keyboards#Standard-keyboard-shortcuts)의 내용을 참조하십시오.

**가급적 짧으면서 단일 단어로 구성된 메뉴 제목을 사용하십시오.** 다양한 디스플레이 크기, 메뉴 막대 아이콘의 표시 여부 등 여러 요인이 메뉴의 간격 및 모양에 영향을 줄 수 있습니다. 단일 단어로 구성된 메뉴 제목은 공간을 적게 차지하고 읽기 쉬우므로 메뉴 막대에 특히 적합합니다. 두 단어 이상으로 구성된 메뉴 제목을 사용해야 하는 경우, 제목식 대문자 표기법을 사용하십시오.

## 앱 메뉴

앱 메뉴는 특정 작업, 문서 또는 윈도우가 아니라 앱 또는 게임에 전체적으로 적용되는 항목을 나열합니다. 활성화된 앱을 사람들이 빨리 식별할 수 있도록 메뉴 막대에 앱 이름이 볼드체로 표시됩니다.

일반적으로 앱 메뉴는 다음과 같은 순서로 메뉴 항목을 포함합니다.

| 메뉴 항목 | 동작 | 지침 |
| --- | --- | --- |
| *앱 이름*에 관하여 | 저작권 및 버전 정보가 포함된 앱의 정보 윈도우를 표시합니다. | 가급적 16자 이하의 짧은 이름을 사용하십시오. 버전 번호를 포함하지 마십시오. |
| 설정… | iPadOS 설정에서 [설정](https://developer.apple.com/kr/design/human-interface-guidelines/settings) 윈도우 또는 앱 페이지를 여십시오. | 앱 수준 설정으로만 사용하십시오. 문서별 설정도 제공하는 경우, 문서별 설정은 파일 메뉴에 넣으십시오. |
| 앱 특화 항목(선택 사항) | 사용자화된 앱 수준 설정 또는 구성 동작을 수행합니다. | 사용자화된 앱 구성 항목을 설정 항목 뒤에 동일한 그룹으로 나열하십시오. |
| 서비스(macOS만 해당) | 현재 상황에 해당하는 시스템 및 기타 앱의 서비스 하위 메뉴를 표시합니다. |  |
| *앱 이름* 가리기(macOS만 해당) | 현재 앱과 앱의 윈도우를 가린 다음, 가장 최근에 사용한 앱을 활성화합니다. | ‘앱 이름에 관하여’ 항목에 제공한 것과 동일한 짧은 앱 이름을 사용하십시오. |
| 기타 가리기(macOS만 해당) | 열려 있는 다른 모든 앱과 해당 앱의 윈도우를 가립니다. |  |
| 모두 보기(macOS만 해당) | 열려 있는 다른 모든 앱과 해당 앱의 윈도우를 현재 앱 윈도우 뒤에 표시합니다. |  |
| *앱 이름* 종료 | 앱을 종료합니다. Option을 누르면 ‘*앱 이름* 종료’가 ‘종료 및 윈도우 유지’로 변경됩니다. | ‘앱 이름에 관하여’ 항목에 제공한 것과 동일한 짧은 앱 이름을 사용하십시오. |

**’앱 이름에 관하여’ 메뉴 항목을 먼저 표시하십시오.** 그룹에서 혼자 나타나도록 ’앱 이름에 관하여’ 메뉴 항목 뒤에 분리자를 포함하십시오.

## 파일 메뉴

파일 메뉴는 앱에서 지원하는 파일 또는 문서를 관리할 수 있는 명령을 포함합니다. 앱에서 처리하는 파일 유형이 없을 경우, 이 메뉴의 이름을 변경하거나 이를 제거할 수 있습니다.

일반적으로 파일 메뉴는 다음과 같은 순서로 메뉴 항목을 포함합니다.

| 메뉴 항목 | 동작 | 지침 |
| --- | --- | --- |
| 새로운 *항목* | 새로운 문서, 파일 또는 윈도우를 생성합니다. | 앱에서 생성하는 항목 유형의 이름을 나타내는 용어를 *항목*에 사용하십시오. 예를 들어, 캘린더는 *이벤트* 및 *캘린더*를 사용합니다. |
| 열기 | 선택된 항목을 열거나, 열려는 항목을 선택할 수 있는 인터페이스를 표시합니다. | 별도의 인터페이스에서 항목을 선택해야 하는 경우, 명령 뒤에 생략 부호가 표시되어 입력이 더 필요함을 알려줍니다. |
| 최근 사용 열기 | 최근 연 문서 및 파일을 선택할 수 있는 하위 메뉴를 표시하며, 일반적으로 *메뉴 지우기* 항목이 포함되어 있습니다. | 하위 메뉴에 사람들이 알아볼 수 있는 문서 및 파일 이름을 나열하십시오. 파일 경로는 표시하지 마십시오. 가장 최근에 연 문서가 처음에 표시되도록 마지막으로 연 순서대로 문서를 나열하십시오. |
| 닫기 | 현재 윈도우 또는 문서를 닫습니다. Option을 누르면 ‘닫기’가 ‘모두 닫기’로 변경됩니다. 탭 기반 윈도우의 경우, ‘닫기’ 대신 ‘탭 닫기’가 표시됩니다. | 탭 기반 윈도우에서는 클릭 또는 탭 한 번으로 전체 윈도우를 닫을 수 있도록 ‘윈도우 닫기’ 항목을 추가하는 것을 고려하십시오. |
| 탭 닫기 | 탭 기반 윈도우에서 현재 탭을 닫습니다. Option을 누르면 ‘탭 닫기’가 ‘다른 탭 닫기’로 변경됩니다. |  |
| 파일 닫기 | 현재 파일 및 관련 윈도우를 모두 닫습니다. | 앱에서 동일한 파일의 여러 보기를 열 수 있는 경우, 이 메뉴 항목을 지원하는 것을 고려하십시오. |
| 저장 | 현재 문서 또는 파일을 저장합니다. | 사람들이 파일 > 저장을 계속 선택할 필요가 없도록 작업 중에 주기적으로 변경 사항을 자동 저장하십시오. 새로운 문서의 경우, 저장할 이름과 위치를 물어보십시오. 여러 포맷으로 파일을 저장할 수 있도록 하려면 저장 시트에서 포맷을 선택할 수 있는 팝업 메뉴를 사용하십시오. |
| 모두 저장 | 열려 있는 모든 문서를 저장합니다. |  |
| 복제 | 현재 문서를 복제하며, 두 문서 모두 열린 상태가 됩니다. Option을 누르면 ‘복제’가 ‘별도 저장’으로 변경됩니다. | 별도 저장, 내보내기, 다음으로 복사, 다음으로 저장과 같은 메뉴 항목보다는 복제를 우선적으로 사용하십시오. 이러한 항목은 원래 파일과 새로운 파일 간의 관계를 나타내지 못하기 때문입니다. |
| 이름 변경… | 현재 문서의 이름을 변경할 수 있습니다. |  |
| 다음으로 이동… | 문서의 새로운 위치를 선택하도록 프롬프트를 표시합니다. |  |
| 다음으로 내보내기… | 이름, 출력 위치 및 내보내기 파일 포맷을 지정하도록 프롬프트를 표시합니다. 파일을 내보낸 후, 현재 문서는 열린 상태가 유지되고 내보낸 파일은 따로 열리지 않습니다. | 앱에서 일반적으로 처리하지 않는 포맷으로 콘텐츠를 내보낼 수 있도록 하는 경우에 ‘다음으로 내보내기’ 항목을 사용하십시오. |
| 다음으로 복귀 | 자동 저장을 켠 경우, 최근 문서 버전과 버전 브라우저를 표시하는 옵션이 나열되어 있는 하위 메뉴를 표시합니다. 복원한 버전을 선택한 후에는 해당 버전이 현재 문서를 대치합니다. |  |
| 페이지 설정… | 용지 크기, 프린트 방향과 같은 프린트 매개변수를 지정하는 패널을 엽니다. 문서는 사람들이 지정하는 프린트 매개변수를 저장할 수 있습니다. | 특정 문서에 적용되는 프린트 매개변수를 지원하려면 ‘페이지 설정’ 항목을 포함하십시오. 프린터 이름과 같이 전역적인 매개변수 또는 프린트 매 수와 같이 자주 변경하는 매개변수는 프린트 패널에 포함됩니다. |
| 프린트… | 프린터로 프린트하거나, 팩스를 보내거나, PDF로 저장할 수 있는 표준 프린트 패널을 엽니다. |  |

## 편집 메뉴

편집 메뉴를 통해 현재 문서 또는 텍스트 컨테이너의 콘텐츠를 변경하고, 클립보드와 상호작용할 수 있습니다. 다수의 편집 명령은 편집 가능한 모든 콘텐츠에 적용되므로 문서 기반이 아닌 앱에서도 편집 메뉴를 유용하게 사용할 수 있습니다.

**찾기 메뉴 항목을 편집 메뉴에 포함할지 결정하십시오.** 예를 들어, 앱에서 파일 또는 다른 대상체 유형을 검색할 수 있는 경우 찾기 메뉴 항목을 파일 메뉴에 포함하는 것이 더 적합할 수 있습니다.

일반적으로 편집 메뉴는 다음과 같은 순서로 상위 레벨 메뉴 항목을 포함합니다.

| 메뉴 항목 | 동작 | 지침 |
| --- | --- | --- |
| 실행 취소 | 이전에 수행한 사용자 작업을 되돌립니다. | 실행 취소되는 대상을 명확히 나타내십시오. 예를 들어, 사람들이 방금 메뉴 항목을 선택한 경우 ‘붙여넣고 스타일 일치 실행 취소’와 같이 항목의 제목을 추가할 수 있습니다. 텍스트 입력 작업의 경우, *입력*이라는 단어를 추가하여 입력 실행 취소를 표시할 수 있습니다. |

| 오려두기 | 선택된 데이터를 제거하고 이를 클립보드에 저장합니다. 클립보드의 이전 콘텐츠는 대치됩니다. |  |

| 변형 | 선택된 텍스트를 변형하는 항목이 포함된 하위 메뉴를 표시합니다. 표준 하위 메뉴에는 대문자로 만들기, 소문자로 만들기, 대문자로 시작 등이 있습니다. |  |

## 포맷 메뉴

포맷 메뉴에서 현재 문서 또는 텍스트 컨테이너의 텍스트 포맷 속성을 조절할 수 있습니다. 앱에서 포맷 지정된 텍스트의 편집을 지원하지 않는 경우 이 메뉴를 제거할 수 있습니다.

일반적으로 포맷 메뉴는 다음과 같은 순서로 상위 레벨 메뉴 항목을 포함합니다.

| 메뉴 항목 | 동작 |
| --- | --- |
| 서체 | 선택된 텍스트의 서체 속성을 조절하는 항목이 포함된 하위 메뉴를 표시합니다. 표준 하위 메뉴에는 서체 보기, 볼드체, 이탤릭체, 밑줄체, 크게, 작게, 색상 보기, 스타일 복사하기, 스타일 붙여넣기 등이 있습니다. |
| 텍스트 | 선택된 텍스트의 텍스트 속성을 조절하는 항목이 포함된 하위 메뉴를 표시합니다. 표준 하위 메뉴에는 왼쪽 정렬, 중앙 정렬, 좌우 정렬, 오른쪽 정렬, 작성 방향, 눈금자 보기, 눈금자 복사하기, 눈금자 붙여넣기 등이 있습니다. |

## 보기 메뉴

보기 메뉴를 통해 앱의 모든 윈도우 모양을 유형에 상관없이 사용자화할 수 있습니다.

> **중요:** 보기 메뉴는 특정 윈도우를 탐색하거나 관리하는 항목을 포함하고 있지 않으며, 이러한 명령은 [윈도우 메뉴](https://developer.apple.com/kr/design/human-interface-guidelines/the-menu-bar#Window-menu)에서 제공합니다.

**앱에서 표준 보기 기능의 일부만 지원하더라도 보기 메뉴를 제공하십시오.** 예를 들어, 앱이 탭 막대, 도구 막대 또는 사이드바를 포함하지 않지만 전체 화면 모드는 지원하는 경우, 전체 화면 모드 시작/종료 메뉴 항목만 포함하는 보기 메뉴를 제공하십시오.

**각각의 보기/가리기 항목 제목이 해당하는 보기의 현재 상태를 반영하도록 하십시오.** 예를 들어, 도구 막대가 가려지면 ‘도구 막대 보기’ 메뉴 항목을 제공하고, 도구 막대가 표시되면 ‘도구 막대 가리기’ 메뉴 항목을 제공하십시오.

일반적으로 보기 메뉴는 다음과 같은 순서로 상위 레벨 메뉴 항목을 포함합니다.

| 메뉴 항목 | 동작 |
| --- | --- |
| 탭 막대 보기/가리기 | 탭 기반 윈도우에서 본문 영역 위에 있는 [탭 막대](https://developer.apple.com/kr/design/human-interface-guidelines/tab-bars)의 표시 여부를 토글합니다. |
| 모든 탭 보기/탭 개요 종료 | 탭 기반 윈도우에서 열려 있는 모든 탭의 개요를 제공하는 보기(Mission Control과 유사)를 시작 및 종료합니다. |
| 도구 막대 보기/가리기 | [도구 막대](https://developer.apple.com/kr/design/human-interface-guidelines/toolbars)가 포함된 윈도우에서 도구 막대의 표시 여부를 토글합니다. |
| 도구 막대 사용자화 | 도구 막대가 포함된 윈도우에서 도구 막대 항목을 사용자화할 수 있는 보기를 엽니다. |
| 사이드바 보기/가리기 | [사이드바](https://developer.apple.com/kr/design/human-interface-guidelines/sidebars)가 포함된 윈도우에서 사이드바의 표시 여부를 토글합니다. |
| 전체 화면 시작/종료 | [전체 화면 사용하기](https://developer.apple.com/kr/design/human-interface-guidelines/going-full-screen)을 지원하는 앱에서 윈도우를 새로운 공간에 전체 화면 크기로 엽니다. |

## 앱 특화 메뉴

앱의 사용자 설정 메뉴는 메뉴 막대의 보기 메뉴와 윈도우 메뉴 사이에 나타납니다. 예를 들어, Safari의 메뉴 막대는 앱에 특화된 메뉴인 방문 기록과 북마크를 포함하고 있습니다.

**사용자 설정 명령을 수행하는 앱 특화 메뉴를 제공하십시오.** 사람들은 특히 앱을 처음 사용하는 경우에 메뉴 막대에서 앱에 특화된 명령을 찾아봅니다. 앱의 다른 위치에서 명령을 사용할 수 있더라도 해당 명령을 메뉴 막대에 표시하는 것이 중요합니다. 메뉴 막대에 명령을 넣으면 쉽게 찾을 수 있고, 키보드 단축키를 할당할 수 있으며, 전체 키보드 접근을 통해 접근성을 향상할 수 있습니다. 메뉴 막대에서 명령을 제거하면 사람들이 해당 명령을 찾는 데 어려움을 겪을 수 있습니다. 자주 사용하지 않거나 고급 명령인 경우에도 마찬가지입니다.

**앱 특화 메뉴에서 앱의 계층을 최대한 반영하십시오.** 예를 들어, Mail은 메일상자, 메시지, 포맷 순서로 메뉴를 나열하는데 이는 이 항목들의 관계가 반영된 순서입니다. 메일상자는 메시지를 포함하고, 메시지는 포맷을 포함하기 때문입니다.

**가장 일반적인 항목순 또는 자주 사용하는 항목순으로 앱 특화 메뉴를 나열하십시오.** 사람들은 목록의 앞쪽에 있는 메뉴가 목록의 뒤쪽에 있는 메뉴보다 더 전문화되어 있을 것으로 예상합니다.

## 윈도우 메뉴

윈도우 메뉴에서 앱의 윈도우를 탐색, 구성 및 관리할 수 있습니다.

> **중요:** 윈도우 메뉴를 통해 윈도우의 모양을 사용자화하거나 윈도우를 닫을 수 없습니다. [보기 메뉴](https://developer.apple.com/kr/design/human-interface-guidelines/the-menu-bar#View-menu)의 명령을 사용하여 윈도우를 사용자화하고, [파일 메뉴](https://developer.apple.com/kr/design/human-interface-guidelines/the-menu-bar#File-menu)의 닫기를 선택하여 윈도우를 닫을 수 있습니다.

**앱에 윈도우가 하나만 있더라도 윈도우 메뉴를 제공하십시오.** 최소화 및 확대/축소 메뉴 항목을 포함하여 전체 키보드 접근을 사용하는 사람들이 키보드를 통해 해당 기능을 실행할 수 있게 하십시오.

**패널을 표시하고 가리는 메뉴 항목을 포함하는 것을 고려하십시오.** [패널](https://developer.apple.com/kr/design/human-interface-guidelines/panels)은 기본 윈도우에서 정보, 구성 옵션 또는 콘텐츠와 상호작용하는 도구를 제공하며, 일반적으로 사람들이 필요로 할 때에만 나타납니다. 서체 패널 또는 텍스트 색상 패널은 포맷 메뉴에 포함되어 있으므로 이러한 패널에 대한 접근을 따로 제공할 필요는 없습니다.

일반적으로 윈도우 메뉴는 다음과 같은 순서로 상위 레벨 메뉴 항목을 포함합니다.

| 메뉴 항목 | 동작 | 지침 |
| --- | --- | --- |
| 최소화 | 활성화된 윈도우를 Dock으로 최소화합니다. Option 키를 누르면 이 항목이 ‘모두 최소화’로 변경됩니다. |  |
| 확대/축소 | 윈도우의 콘텐츠에 적합하도록 미리 정의된 크기와 사람들이 설정한 윈도우 크기 간에 토글합니다. Option 키를 누르면 이 항목이 ‘모두 확대/축소’로 변경됩니다. | 확대/축소를 사용하여 전체 화면 모드를 시작하거나 종료하지 마십시오. 해당 기능은 [보기 메뉴](https://developer.apple.com/kr/design/human-interface-guidelines/the-menu-bar#View-menu)에서 지원합니다. |
| 이전 탭 보기 | 탭 기반 윈도우에서 현재 탭 이전의 탭을 표시합니다. |  |
| 다음 탭 보기 | 탭 기반 윈도우에서 현재 탭 다음의 탭을 표시합니다. |  |
| 새로운 윈도우로 탭 이동 | 현재 탭을 새로운 윈도우에서 엽니다. |  |
| 모든 윈도우 통합 | 열려 있는 모든 윈도우를 탭으로 구성된 하나의 윈도우로 통합합니다. |  |
| 전체 화면 시작/종료 | [전체 화면 사용하기](https://developer.apple.com/kr/design/human-interface-guidelines/going-full-screen)을 지원하는 앱에서 윈도우를 새로운 공간에 전체 화면 크기로 엽니다. | 앱에 보기 메뉴가 없을 때에만 이 항목을 윈도우 메뉴에 포함하십시오. 이 경우, 최소화 및 확대/축소 메뉴 항목을 별도로 계속 제공하십시오. |
| 모두 앞으로 가져오기 | 화면상의 위치, 크기 및 레이어 순서를 유지하면서 앱의 열려 있는 모든 윈도우를 앞으로 가져옵니다. (Dock의 앱 아이콘을 클릭하면 동일한 효과가 발생합니다.) Option 키를 누르면 이 항목이 ‘차례대로 정렬’로 변경되며, 앱 윈도우를 정돈된 타일 형태로 정렬하여 앞으로 가져올 수 있습니다. |  |
| *열려 있는 앱 특화 윈도우의 이름* | 선택된 윈도우를 앞으로 가져옵니다. | 쉽게 찾을 수 있도록 현재 열려 있는 윈도우를 알파벳 순서로 나열하십시오. 패널 또는 다른 모달 뷰를 나열하지 마십시오. |

## 도움말 메뉴

메뉴 막대의 뒤쪽에 있는 도움말 메뉴를 통해 앱의 도움말 문서를 확인할 수 있습니다. 해당 문서가 Help Book 포맷인 경우, macOS에서 자동으로 도움말 메뉴 상단에 검색 필드를 포함합니다.

| 메뉴 항목 | 동작 | 지침 |
| --- | --- | --- |
| Apple에 *앱 이름* 피드백 보내기 | 피드백을 제출할 수 있는 피드백 지원을 엽니다. |  |
| *앱 이름* 도움말 | 콘텐츠가 Help Book 포맷인 경우, 내장 도움말 뷰어에서 콘텐츠를 엽니다. |  |
| *추가 항목* |  | 기본 도움말 문서와 추가 항목 사이에 분리자를 사용하십시오. 추가 항목은 등록 정보 또는 릴리즈 노트 등이 될 수 있습니다. 도움말 메뉴에 항목을 적게 표시하십시오. 항목이 너무 많으면 사람들이 부담을 느낄 수 있습니다. 또는 도움말 문서에서 추가 항목을 링크하는 것을 고려하십시오. |

지침을 보려면 [도움말 제공하기](https://developer.apple.com/kr/design/human-interface-guidelines/offering-help)의 내용을 참조하십시오. 개발자 지침을 보려면 [NSHelpManager](https://developer.apple.com/documentation/appkit/nshelpmanager)의 내용을 참조하십시오.

## 동적 메뉴 항목

흔하지는 않지만 *동적 메뉴 항목*을 표시하는 것이 적합한 경우가 있습니다. 동적 메뉴 항목은 보조 키(Control, Option, Shift 또는 Command)를 누르면서 선택할 때 동작이 변경되는 메뉴 항목입니다. 예를 들어, 윈도우 메뉴의 *최소화* 항목은 Option 키를 누를 때 *모두 최소화*로 변경됩니다.

**동적 메뉴 항목이 작업을 수행하는 유일한 방법이 되어서는 안 됩니다.** 동적 메뉴 항목은 기본적으로 가려져 있으므로, 다른 방법으로도 수행 가능한 고급 동작을 손쉽게 실행하기 위한 목적으로 사용하는 것이 가장 적합합니다. 예를 들어, 윈도우 메뉴에서 *모두 최소화* 동적 메뉴 항목을 발견하지 못하더라도 열려 있는 각각의 윈도우를 최소화하여 같은 작업을 수행할 수 있습니다.

**동적 메뉴 항목은 주로 메뉴 막대 메뉴에서 사용하십시오.** 빠른 메뉴 또는 Dock 메뉴에 동적 메뉴 항목을 추가하면 해당 항목을 발견하기 더 어려울 수 있습니다.

**보조 키를 하나만 사용하여 동적 메뉴 항목을 표시하십시오.** 메뉴를 열고 메뉴 항목을 선택하면서 동시에 두 개 이상의 키를 누르는 것은 부자연스럽게 느껴질 수 있으며, 동적 동작을 쉽게 발견하지 못하게 만듭니다. 개발자 지침을 보려면 [isAlternate](https://developer.apple.com/documentation/appkit/nsmenuitem/isalternate)의 내용을 참조하십시오.

> **팁:** macOS는 동적 메뉴 항목을 비롯하여 너비가 가장 긴 항목이 잘 표시되도록 메뉴 너비를 자동으로 설정합니다.

## 플랫폼 고려 사항

*iOS, tvOS, visionOS 또는 watchOS에서는 지원되지 않습니다.*

### iPadOS

메뉴 막대는 앱 또는 게임의 상위 레벨 메뉴를 표시합니다. 여기에는 시스템에서 제공하는 메뉴와 추가하기로 선택한 사용자 설정 메뉴가 모두 포함됩니다. 포인터를 화면 상단의 가장자리로 이동하거나 아래로 쓸어내리면 메뉴 막대를 표시할 수 있습니다. 메뉴 막대가 표시되면 화면 상단 가장자리의 [상태 막대](https://developer.apple.com/kr/design/human-interface-guidelines/status-bars)와 동일한 세로 공간을 차지합니다.

macOS 메뉴 막대와 마찬가지로 iPadOS 메뉴 막대는 사람들이 능숙하게 앱 기능을 알아보고 필요한 명령을 찾으며 키보드 단축키를 검색할 수 있는 방법을 제공합니다.  대부분 유사한 기능을 제공하지만 플랫폼별 메뉴 막대에는 몇 가지 차이점이 있습니다.

|  | iPadOS | macOS |
| --- | --- | --- |
| 메뉴 막대 가시성 | 표시할 때까지 가려짐 | 기본적으로 표시 |
| 수평 정렬 | 중앙 | 앞쪽 |
| 메뉴 막대 아이콘 | 사용할 수 없음 | 시스템 기본 항목 및 사용자 설정 항목 |
| 윈도우 제어기 | 앱이 전체 화면 모드일 때 메뉴 막대에 제공됨 | 메뉴 막대에 제공되지 않음 |
| Apple 메뉴 | 사용할 수 없음 | 항상 사용할 수 있음 |
| 앱 메뉴 | 정보, 서비스, 앱 가시성 관련 항목은 사용할 수 없음 | 항상 사용할 수 있음 |

**앱을 전체 화면을 실행할 때 메뉴 막대가 종종 가려져 있기 때문에 사람들이 UI를 통해 앱의 모든 기능에 접근할 수 있도록 하십시오.**  특히 하드웨어 키보드를 연결한 경우에만 표시되는 동적 메뉴 항목에 할당된 작업을 수행할 수 있는 다른 방법을 항상 제공하십시오. 메뉴 막대가 다른 곳에 배치하기에 애매한 기능들을 무분별하게 모아놓은 공간이 되지 않도록 하십시오.

**iPadOS 설정에서 앱 페이지를 여는 경로는 앱 이름 > 설정 메뉴 항목으로 지정하십시오.** 앱에 자체 내부 환경설정 영역이 있는 경우 동일한 그룹의 설정 아래에 있는 별도의 메뉴 항목을 통해 해당 경로로 연결하십시오. 다른 사용자 설정 앱의 전체 구성 옵션도 이 섹션에 배치하십시오.

**탭 스타일 탐색이 포함된 앱의 경우, 보기 메뉴에서 각 탭을 메뉴 항목으로 추가하는 것을 고려하십시오.** 각 탭은 앱의 다른 보기이기 때문에 보기 메뉴는 탭 간에 탐색하기 위한 추가 방법을 제공하는 자연스러운 장소입니다. 이렇게 할 경우, 탐색을 더욱 편리하게 하기 위해 각 탭에 키 바인딩을 할당하는 것을 고려하십시오.

**메뉴 항목을 하위 메뉴로 그룹화하여 세로 공간을 절약하는 것을 고려하십시오.** iPad의 메뉴 항목 행은 Mac보다 더 많은 공간을 사용하여 더 쉽게 탭할 수 있습니다. 이러한 이유와 함께 일부 iPad의 화면 크기가 더 작기 때문에 Mac의 메뉴 막대보다 더욱 자주 관련 항목을 하위 메뉴로 그룹화하는 것이 도움이 될 수 있습니다.

### macOS

macOS의 메뉴 막대에는 Apple 메뉴가 제공되며 항상 메뉴 막대 앞쪽에 첫 번째 항목으로 표시됩니다. Apple 메뉴에는 항상 사용할 수 있는 시스템 정의 메뉴 항목이 있으며 이 항목은 수정하거나 제거할 수 없습니다. 공간이 있을 경우, 시스템은 메뉴 막대의 뒤쪽 끝에 메뉴 막대 아이콘을 표시할 수도 있습니다. 지침을 보려면 [메뉴 막대 아이콘](https://developer.apple.com/kr/design/human-interface-guidelines/the-menu-bar#Menu-bar-extras)의 내용을 참조하십시오.

메뉴 막대의 공간이 제한되어 있는 경우, 시스템은 메뉴와 필수 메뉴 막대 아이콘을 우선적으로 표시합니다. 메뉴를 항상 읽을 수 있도록 시스템이 제목 사이의 공간을 줄이고 필요할 경우 제목을 자를 수도 있습니다.

전체 화면 모드를 시작할 경우 일반적으로 메뉴 막대가 가려지며 화면 상단에 포인터를 이동하면 메뉴 막대가 표시됩니다. 지침을 보려면 [전체 화면 사용하기](https://developer.apple.com/kr/design/human-interface-guidelines/going-full-screen)의 내용을 참조하십시오.

#### 메뉴 막대 아이콘

앱이 가장 앞에 있지 않더라도 앱을 실행 중이라면 메뉴 막대 아이콘이 메뉴 막대에서 앱에 특화된 기능을 아이콘으로 표시합니다. 메뉴 막대 아이콘은 메뉴 막대에서 앱 메뉴의 반대쪽에 있습니다. 개발자 지침을 보려면 [MenuBarExtra](https://developer.apple.com/documentation/swiftui/menubarextra)의 내용을 참조하십시오.

필요할 경우 시스템은 앱 메뉴 공간을 확보하기 위해 메뉴 막대 아이콘을 가립니다. 이와 비슷하게, 메뉴 막대 아이콘이 너무 많은 경우 앱 메뉴가 복잡해지지 않도록 시스템이 일부 항목을 가릴 수 있습니다.

![입력 메뉴 막대 아이콘 및 해당 메뉴의 스크린샷.](https://developer.apple.com/images/com.apple.HIG/kr/menu-bar-extras@2x.png)

**메뉴 막대 아이콘을 나타내기 위해 기호를 사용하는 것을 고려하십시오.** [아이콘](https://developer.apple.com/kr/design/human-interface-guidelines/icons)을 생성하거나 [SF Symbols](https://developer.apple.com/kr/design/human-interface-guidelines/sf-symbols) 중 하나를 선택하고 그대로 또는 필요에 따라 사용자화하여 사용할 수 있습니다. 인터페이스 아이콘과 기호 모두 검은색과 투명색을 사용하여 모양을 정의합니다. 시스템은 각 이미지의 검은색 영역에 다른 색상을 적용할 수 있으므로 메뉴 막대의 색상이 어둡거나 밝아도 잘 표시되고, 메뉴 막대 아이콘이 선택되었을 경우에도 잘 표시됩니다. 메뉴 막대의 높이는 24pt입니다.

**메뉴 막대 아이콘을 클릭할 때 팝오버가 아니라 메뉴를 표시하십시오.** 표시하려는 앱 기능이 너무 복잡하여 메뉴를 사용하기 어려운 경우가 아니라면 [팝오버](https://developer.apple.com/kr/design/human-interface-guidelines/popovers)로 표시하지 마십시오.

**앱이 아니라 사람들이 메뉴 막대에 메뉴 막대 아이콘을 표시할지 여부를 결정하게 하십시오.** 일반적으로 사람들은 앱의 설정 윈도우에서 설정을 변경하여 메뉴 막대에 메뉴 막대 아이콘을 추가합니다. 이러한 기능이 있다는 것을 알 수 있도록 설정 중에 해당 옵션을 제공하는 것을 고려하십시오.

**메뉴 막대 아이콘의 표시 상태에 의존하지 마십시오.** 시스템은 메뉴 막대 아이콘을 자주 가리고 표시합니다. 또한 사람들이 어떤 메뉴 막대 아이콘을 선택하여 표시하는지 또는 메뉴 막대 아이콘의 위치가 어디인지 정확히 예측할 수 없습니다.

**다른 방법으로도 앱 특화 기능을 표시하는 것을 고려하십시오.** 예를 들어, 앱의 Dock 아이콘을 Control-클릭할 때 나타나는 [Dock 메뉴](https://developer.apple.com/kr/design/human-interface-guidelines/dock-menus)를 제공할 수 있습니다. 메뉴 막대 아이콘은 가리거나 사용하지 않도록 선택할 수 있지만 Dock 메뉴는 앱이 실행될 때 항상 제공됩니다.
