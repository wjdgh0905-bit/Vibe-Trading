# 경고

Source: https://developer.apple.com/kr/design/human-interface-guidelines/alerts

> 경고는 사람들에게 곧바로 필요한 중요한 정보를 제공합니다.

![제목, 설명, 기본 버튼 및 보조 버튼이 포함된 스타일화된 경고 모형이 표시되어 있음. 여섯 가지 색상으로 된 기존 Apple 로고의 빨간색을 은은하게 반영하는 빨간색 색조가 이미지에 적용됨.](https://developer.apple.com/images/com.apple.HIG/components-alert-intro@2x.png)

예를 들어, 경고는 사람들에게 문제에 대해 알려주고, 동작이 데이터를 삭제할 수 있을 때 이를 경고하며, 구입 또는 사람들이 시작한 기타 중요한 동작을 확인할 기회를 제공할 수 있습니다.

## 모범 사례

**경고를 절제해서 사용하십시오.** 경고는 사람들에게 중요한 정보를 제공하지만, 해당 작업을 하기 위해 현재 작업이 중단됩니다. 각각의 경고가 중요한 정보와 유용한 동작만 제공하는 것을 확실히 함으로써 사람들이 경고에 집중할 수 있도록 유도하십시오.

**단순히 정보를 제공하기 위해 경고를 사용하지 마십시오.** 사람들은 정보를 제공하지만 실행 불가능한 경고의 방해를 받고 싶어 하지 않습니다. 정보만 제공해야 하는 경우, 가급적 관련 상황 내에서 이를 전달할 수 있는 대체 방법을 찾으십시오. 예를 들어, 서버 연결을 사용할 수 없는 경우, Mail에는 사람들이 더 자세히 알아보기 위해 선택할 수 있는 표시기가 표시됩니다.

**일반적이고 실행 취소할 수 있는 동작은 삭제 동작인 경우에도 경고를 표시하지 마십시오.** 예를 들어, 사람들이 이메일 또는 파일을 삭제할 때마다 사람들에게 데이터 유실에 대해 경고를 보낼 필요가 없습니다. 그 이유는 그들이 데이터를 폐기할 의도로 이를 수행하기 때문이며, 해당 동작은 실행 취소할 수 있습니다. 이에 반해, 사람들이 실행 취소할 수 없는 일반적이지 않은 삭제 동작을 취하면, 그들이 의도치 않게 동작을 시작했을 경우에 대비해서 경고를 표시하는 것이 중요합니다.

**앱이 시작되면 경고를 표시하지 마십시오.** 사람들이 앱을 여는 순간 새롭거나 중요한 정보에 대해 사람들에게 알려주어야 하는 경우, 해당 정보를 쉽게 찾을 수 있도록 하는 방법을 설계하십시오. 네트워크 연결 없음과 같이 앱이 실행 시 문제를 감지한 경우, 사람들에게 알릴 수 있는 대체 방법을 고려하십시오. 예를 들어, 캐시된 데이터 또는 위치 지정자 데이터 및 문제를 설명하는 방해되지 않는 레이블을 표시할 수 있습니다.

## 콘텐츠

모든 플랫폼에서 경고는 제목, 선택적 정보 제공 텍스트 및 최대 세 개의 버튼을 표시합니다. 일부 플랫폼에서 경고는 추가 요소를 포함합니다.

- iOS, iPadOS, macOS 및 visionOS에서 경고는 텍스트 필드를 포함할 수 있습니다.
- macOS 및 visionOS의 경고는 아이콘 및 액세서리 보기를 포함할 수 있습니다.
- macOS 경고는 표시 제한 [체크상자](https://developer.apple.com/kr/design/human-interface-guidelines/toggles#Checkboxes) 및 [도움말 버튼](https://developer.apple.com/kr/design/human-interface-guidelines/buttons#Help-buttons)을 추가할 수 있습니다.

**모든 경고 문구에서 직접적인 스타일과 중립적이고 이해하기 쉬운 톤을 사용하십시오.** 경고는 종종 문제 및 심각한 상황을 설명하므로, 간접적이거나 비난적인 스타일을 피하거나, 문제의 심각도를 가리지 마십시오.

**명확하고 간결하게 상황을 설명하는 제목을 작성하십시오.** 사람들이 빠르게 상황을 이해하도록 도와주어야 하므로, 장황하지 않고 완전하고 구체적이어야 합니다. 가능한 한, 발생한 일과 그 일이 발생한 상황 및 이유를 설명하십시오. 유용한 정보(예: ‘오류’ 또는 ‘오류 329347 발생’)를 전달하지 않는 제목은 작성하지 말고 세 줄 이상으로 줄바꿈되는 너무 긴 제목도 피하십시오. 제목이 완전한 문장인 경우, [sentence-style capitalization](https://help.apple.com/applestyleguide/#/apsgb744e4a3?sub=apdca93e113f1d64)(문장식 대문자 표기법)과 적절한 마침표를 사용하십시오. 제목이 파편적인 문장인 경우, 제목식 대문자 표기법을 사용하고, 마침표를 추가하지 마십시오.

**가치를 더할 경우에만 정보 제공 텍스트를 포함하십시오.** 정보 제공 메시지를 추가해야 하는 경우, 완전한 문장, 문장식 대문자 표기법 및 적절한 구두점을 사용하여 가능한 한 짧게 유지하십시오.

**경고 버튼을 설명하지 마십시오.** 경고 텍스트 및 버튼 제목이 명확한 경우, 버튼이 수행하는 내용을 설명해야 할 필요가 없습니다. 드물지만 버튼 선택에 대한 지침을 제공해야 하는 경우, 사람들의 현재 기기 및 상호작용 방법을 고려하여 *선택*과 같은 용어를 사용하고, 인용 부호 없이 정확한 제목을 사용하여 해당 버튼을 언급하십시오. 지침을 보려면 [버튼](https://developer.apple.com/kr/design/human-interface-guidelines/alerts#Buttons)의 내용을 참조하십시오.

**지원할 경우, 상황을 해결하기 위해 사람들의 입력이 필요한 경우에만 텍스트 필드를 포함하십시오.** 예를 들어, 암호를 수신하기 위해 보안 텍스트 필드를 표시해야 할 수 있습니다.

## 버튼

**간결하고 논리적인 버튼 제목을 생성하십시오.** 버튼 선택의 결과를 설명하는 한 단어 또는 두 단어 제목을 사용하십시오. 가급적 경고 텍스트와 직접 관련된 동사 및 동사 구를 사용하십시오(예: ‘모두 보기’, ‘답장’ 또는 ‘무시’). 정보 전달 경고에서만 승인에 대해 ‘확인’을 사용할 수 있으며 ‘예’ 및 ‘아니요’ 사용을 피합니다. 경고의 동작을 취소하는 버튼의 제목을 지정하려면 항상 ‘취소’를 사용하십시오. 모든 버튼 제목에서와 마찬가지로 마침표 없이 [sentence-style capitalization](https://help.apple.com/applestyleguide/#/apsgb744e4a3?sub=apdca93e113f1d64)(제목식 대문자 표기법)을 사용하십시오.

**경고가 순전히 정보 전달을 위한 것이 아니라면 ‘확인’을 기본 버튼으로 사용하지 마십시오.** ‘확인’의 의미는 사람들에게 어떤 작업을 수행하고 싶다는 확인을 요청하는 경고에서도 명확하지 않을 수 있습니다. 예를 들어, ‘확인’의 의미가 ‘좋아요, 동작을 완료하고 싶습니다’ 또는 ‘알겠어요, 이제 나의 동작으로 인해 초래되었을 부정적인 결과를 이해합니다’ 중 무엇인지 알 수 없습니다. ‘지우기’, ‘변환’ 또는 ‘삭제’와 같은 구체적인 버튼 제목은 사람들이 자신이 수행 중인 동작을 이해하도록 도와줍니다.

**사람들이 예상하는 위치에 버튼을 배치하십시오.** 일반적으로 사람들이 가장 많이 선택할 만한 버튼을 버튼 행의 뒤쪽이나 버튼 스택의 상단에 배치하십시오. 항상 기본 버튼을 행의 뒤쪽이나 스택 상단에 배치하십시오. 취소 버튼은 일반적으로 행의 앞쪽이나 스택 하단에 있습니다.

**사람들이 의도적으로 선택하지 않은 삭제 동작을 수행하는 버튼을 식별하려면 삭제 스타일을 사용하십시오.** 예를 들어, 사람들이 의도적으로 휴지통 비우기와 같은 삭제 동작을 선택한 경우 버튼이 사람의 원래 의도를 수행하기 때문에 경고는 휴지통 비우기 버튼에 삭제 스타일을 적용하지 않습니다. 이런 경우, 의도적으로 선택한 휴지통 비우기 동작을 확인하기 위해 Return 키를 누르는 편리함이 해당 버튼이 삭제 동작이라는 것을 다시 확인하는 이점보다 더 큽니다. 이와 반대로, 사람들은 원래 의도하지 않은 삭제 동작을 수행할 수 있는 버튼에 주의를 집중시키는 경고를 선호합니다.

**삭제 동작이 있는 경우, 사람들이 해당 동작을 피할 수 있는 명확하고 안전한 방법을 제공하도록 취소 버튼을 포함하십시오.** 경고의 동작을 취소하는 버튼의 경우 항상 제목을 ‘취소’로 사용하십시오. 취소 버튼을 기본 버튼으로 설정해서는 안 되는 점에 유의하십시오. 사람들이 경고를 읽도록 유도하고, 경고를 닫기 위해 자동적으로 Return을 누르지 않게 하려는 경우, 모든 버튼을 기본 버튼으로 설정하는 것을 피하십시오. 이와 비슷하게, 기본 버튼이기도 한 단일 버튼이 포함된 경고를 표시해야 하는 경우 취소 버튼이 아닌 완료 버튼을 사용하십시오.

**적합한 경우 경고를 취소할 수 있는 대체 방법을 제공하십시오.** 취소 버튼을 선택하는 것 외에도 사람들은 키보드 단축키 또는 기타 빠른 방법을 사용하여 화면상의 경고를 취소하고 싶어 합니다. 예를 들어 다음과 같습니다.

| 동작 | 플랫폼 |
| --- | --- |
| 홈 화면으로 나가기 | iOS, iPadOS |
| 연결된 키보드에서 Escape(Esc) 또는 Command-마침표(.) 누르기 | iOS, iPadOS, macOS, visionOS |
| 리모컨에서 메뉴 누르기 | tvOS |

## 플랫폼 고려 사항

*tvOS 또는 watchOS에 대한 추가 고려 사항은 없습니다.*

### iOS, iPadOS

**의도적인 동작과 관련된 선택을 제공하려면 경고가 아닌 동작 시트를 사용하십시오.** 예를 들어, 사람들이 편집 중인 Mail 메시지를 취소하면 동작 시트는 편집 내용(또는 전체 임시 저장) 삭제, 임시 저장, 또는 편집으로 돌아가기와 같이 세 개의 선택 사항을 제공합니다. 또한 경고는 내용이 제거되는 결과를 초래하는 동작을 사람들이 확인하거나 취소하도록 도울 수는 있지만, 해당 동작과 관련된 추가 선택은 제공하지 않습니다. 지침을 보려면 [동작 시트](https://developer.apple.com/kr/design/human-interface-guidelines/action-sheets)의 내용을 참조하십시오.

**가능할 경우, 스크롤되는 경고를 표시하지 마십시오.** 텍스트 크기가 충분히 큰 경우 경고를 스크롤될 수 있지만 경고 제목을 짧게 유지하고 필요한 경우에만 짧은 메시지를 포함하여 스크롤 가능성을 최소화하십시오.

### macOS

macOS는 경고에 앱 아이콘을 자동으로 표시하지만 대체 아이콘 또는 기호를 제공할 수 있습니다. 또한 macOS에서는 다음을 수행할 수 있습니다.

- 동일한 경고가 그 다음에 발생하지 않도록 사람들이 억제할 수 있는 반복 경고를 구성합니다.
- 추가 정보를 제공해야 하는 경우 사용자 설정 보기를 추가합니다(개발자 지침을 보려면 [accessoryView](https://developer.apple.com/documentation/appkit/nsalert/accessoryview)의 내용 참조).
- 도움말 문서를 여는 도움말 버튼을 포함합니다([도움말 버튼](https://developer.apple.com/kr/design/human-interface-guidelines/buttons#Help-buttons)의 내용 참조).

**주의 기호를 절제해서 사용하십시오.** 경고에 `exclamationmark.triangle`과 같은 주의 기호를 너무 자주 사용하면 중요성이 감소합니다. 예상치 못한 데이터 유실이 발생할 수 있는 동작을 확인할 때와 같이 추가적인 주의가 정말로 필요한 경우에만 해당 기호를 사용하십시오. 저장 또는 휴지통 비우기와 같이 데이터를 덮어쓰거나 제거하는 것이 유일한 목적인 작업의 경우 해당 기호를 사용하지 마십시오.

### visionOS

공유 공간에서 앱을 실행 중일 때 visionOS는 z축을 따라 살짝 앞으로 앱 윈도우 앞에 경고를 표시합니다.

[video: visionOS의 공유 공간에서 실행 중인 Freeform 앱의 경고가 표시된 비디오. 비디오를 재생하면 누군가가 최근 삭제된 Freeform 보드를 영구적으로 삭제하도록 선택함. 그러면 확인을 위해 Freeform 윈도우 앞에 경고가 나타남.]

경고를 닫지 않고 윈도우를 이동하는 경우, 해당 경고는 윈도우에 고정된 상태로 유지됩니다. 전체 공간에서 앱을 실행 중인 경우, 시스템은 착용자의 [시야](https://developer.apple.com/kr/design/human-interface-guidelines/spatial-layout#Field-of-view) 중앙에 경고를 표시합니다.

[video: visionOS의 공유 공간에서 실행 중인 Freeform 앱의 경고가 표시된 비디오. 비디오를 재생하면 누군가가 최근 삭제된 Freeform 보드를 영구적으로 삭제하도록 선택함. 그러면 확인을 위해 Freeform 윈도우 앞에 경고가 나타남. 경고를 닫지 않아 공유 공간에서 Freeform 윈도우를 이동할 때 경고가 Freeform 윈도우에 고정됨.]

visionOS 경고에서 액세서리 보기를 표시해야 하는 경우, 최대 높이가 154pt이고 모서리 반경이 16pt인 보기를 생성하십시오.
